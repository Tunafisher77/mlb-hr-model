# Production Audit and Upgrade Boundary

Audit date: 2026-08-10

## Confirmed production architecture

| Component | Production file/function | Current behavior |
| --- | --- | --- |
| HR selection | `run_daily_mlb_hr_picks.py` | V16.2, nine published targets, statistics-only ranking |
| Game selection | `run_daily_mlb_game_picks.py` | V2.1.1, seven emailed game picks, statistics-only ranking |
| HR schedule | `.github/workflows/main.yml` | 11:30 UTC daily plus manual dispatch |
| Game schedule | `.github/workflows/game_picks.yml` | 11:45 UTC daily plus manual dispatch |
| HR email source | `Email Summary` | Fresh Eastern-date report generated by the HR model |
| Game email source | `Game Email Summary` | Fresh Eastern-date report generated by the Game model |
| Email delivery | Apps Script `sendHrEmailIfFresh` and `sendGameEmailIfFresh` | Hourly checks, stale-date guard, send-once Script Properties |
| Shared output | `Daily MLB HR Picks Scorecard` | One workbook containing HR and Game tabs |

## Frozen selection boundary

The Game and HR Python scripts and their two workflows are frozen by SHA-256 in
`FROZEN_MODEL_BASELINE.json`. Tracking must not change:

- model features, weights, formulas, eligibility, ranking, confidence, or output order;
- official schedule, probable-pitcher, venue, park, or weather behavior;
- existing Sheet tabs or email-summary contents;
- Apps Script delivery, recipients, freshness checks, or triggers.

## Tracking findings

- Current Game predictions are overwritten daily in `Game Picks`.
- Current `Game Results` is not populated by V2.1.1.
- The workbook contains an older June `Game Prediction History` from a different V2.3 experiment; it is not the current production tracker.
- HR grading is explicitly manual in V16.2.
- Legacy HR tabs contain header migrations and shifted historical rows, so `Daily Picks` is not safe as a new tracking source.
- Current HR `Model Results` contains the correct `gamePk` and matchup fields needed to snapshot the published top nine.
- Dormant odds-related functions exist in the HR source but are not called by `main()` and receive no secret in the active workflow. The new tracker does not import or use them.

## Approved implementation boundary

The new tracker is an independent module and workflow. It reads only published output,
writes only new `Tracking - ...` tabs, and grades from official MLB game feeds. It uses
the existing Google service-account secret and does not require Apps Script changes.
